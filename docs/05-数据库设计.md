# 05 数据库设计

> 可执行 DDL/种子数据：`backend/sql/01-schema.sql`、`backend/sql/02-seed.sql`
> 本地账号：`recycle` / `recycle@Dev123`，库名 `recycle`（与 `deploy/docker-compose.local.yml` 一致）

## 约定

- InnoDB + utf8mb4，主键 BIGINT（应用侧雪花，种子数据用固定 ID）
- 公共字段：`create_time` / `update_time` / `deleted`（MyBatis-Plus 逻辑删除）
- 金额 `DECIMAL(10,2)`/`DECIMAL(12,2)`，重量 `DECIMAL(10,3)`，经纬度 `DECIMAL(10,7)`
- 订单状态：`PENDING/ACCEPTED/SERVING/WEIGHED/COMPLETED/CANCELLED`
- `order_item.item_type`：`ESTIMATE`（下单预估+价格快照） / `ACTUAL`（称重实收+价格快照）
- `sku_price.city_code` 默认 `ALL`，本期不按城市过滤
- `user.balance` + `wallet_ledger` 预留，不开发资金接口

## 索引与查询要点（与已落库 SQL 对齐）

| 场景 | 已建索引 | 说明 |
| --- | --- | --- |
| 接单大厅 | `recycle_order(status, create_time)` + 站点经纬度 | 先按 PENDING 过滤，距离在应用层/边界框计算 |
| 取当日价 | `sku_price(sku_id, city_code, effective_at)` | `effective_at <= now` 最新一条，本期 `city_code=ALL` |
| 用户订单 | `recycle_order(user_id, status)` | C 端 Tab |
| 门店订单 | `recycle_order(station_id, status)` | B 端列表 |
| 抢单 | `UPDATE ... WHERE id=? AND status='PENDING'` | 影响行数 0 即已被抢 |
| 登录手机号 | `user.uk_user_phone` | 软删后同号需换号或改唯一策略 |

本期 **不启用** 钱包三表拆分：`user.balance` + `wallet_ledger` 已预留。优惠券、城市开通表按需 `CREATE TABLE` / `ADD COLUMN`，不改现有列语义。

落地实现以 `backend/sql/*.sql` 为准（雪花 ID、字符串状态枚举，与 `docs/01`/`docs/06` 一致）。另有一份 AUTO_INCREMENT + TINYINT 枚举的备选设计未采用，避免与正在编码的实体映射冲突。
